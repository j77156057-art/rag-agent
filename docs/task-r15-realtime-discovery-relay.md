## 评审后的三项优化（AI-F，2026-09-30）

1. **触发句改成自然口语**（见上 R15-0 第 2 条的修订）—— 原标记会被朗读出来，是语音场景的硬伤。
2. **「交给 AI 排查」改附「报警当刻」的画面快照**（原来是附**当前帧**）：模型说的是几秒前看到的问题，
   用户过一会儿才点排查，那时画面可能已变 —— 拿当前帧去核实等于核实错了对象。现在弹横幅那一刻
   就把帧快照进提醒对象；拿不到快照才退回当前帧，并在 prompt 里如实写明是"当前画面"。
3. **跨来源合并**：抽帧视觉模型与实时模型是两条独立观测链，同一个问题会各弹一条横幅。新增纯函数
   `sameVisualFocus()`（汉字二元组重叠率 ≥0.5，且**字数太少不判**——避免「报错」两个字随便撞上就
   误合并），在**渲染时**计算：近 20 秒内判为同一处就只渲染**一条合并横幅**，两边原文都保留
   （合并是为了少一条重复横幅，不是为了隐藏信息）。

**本轮验证**：`test_live_stream_control.py` + `test_realtime_gateway_bridge.py` **38 passed**；
`test_realtime_provider.py` + `test_realtime_protocol_contract.py` **90 passed**；前端 `npm run build`
（含 typecheck）通过且合并横幅/未核实措辞进包；全量套件 **2415 passed / 6 skipped / 0 failed**。

## 第二批优化：评审后剩下三条里做了两条（AI-F，2026-09-30）

**③ 「交给 AI 排查」不再复用 `app_interface_inspect`** —— 这是**功能错误**，不是体验瑕疵：
那段系统提示写的是「本轮用户意图**就是**触发『浏览当前界面』，请直接执行，不要回答『没有新问题』」，
与 prompt 里"核实这条提醒"**互相矛盾**，会把 Agent 带成泛泛扫一眼界面。而这是 C **唯一的用户主动
入口**，每次点击都受影响。现在改用专用 `uiContext=verify_realtime_alert`，提示写清：
这条提醒是实时模型自述、**未核实、可能幻觉**，附件是**报出它那一刻**的画面（不是当前画面）；
围绕这一条核实，确认没问题或证据不足就直说没找到证据、**不要为了交差编造问题**。

**① 忽略过的提醒在窗口期内不再弹** —— 后端相似度去重只有 45 秒窗口，过了窗口同一处会再弹，
用户刚点完「忽略」又看到同一条会以为按钮没生效。新增两个纯函数
`isDismissedVisualAlert()` / `pruneDismissedVisualAlerts()`（复用 `sameVisualFocus` 判"同一处"，
10 分钟窗口、最多 20 条、超窗自动裁掉），忽略时记下这一处、新提醒到达时先查。

**仍未做（建议等 R15-3 的误报/漏报数字再定）**：② 同一轮多条异常被 2s 全局节流砍掉 —— 轮次结束
才发，可合并成一条；但一轮里报两个**不同**异常很罕见，用户更在意"有没有提醒"而不是"两条都提醒"，
改动要动网关合并逻辑 + 补测试，性价比最低。

## R15-0 决定记录（2026-09-30）

1. **载体：新增 `model.observation` 服务端事件。** 事件含 `source: "realtime-model"`、
   `verified: false`、`text`、`captured_at`，并同步更新 Python 与 TypeScript 封闭词汇表。
   这项协议改动由 `/root` 执行。它与 `video.observation` 完全分开，因此抽帧链路中
   `ok:false` / `audit=unavailable|error` 的关闭分支不会处理或关闭会话。
2. **触发：~~固定前缀 `【疑似异常】`~~ → 已改为「句首口语」**（AI-F 优化，2026-09-30，见下）。
   接受以触发句开头的助手轮次；普通文本和用户转写不回流。等模型轮次结束后再产生提醒，避免暴露半句。

   **为什么改**：实时模型在**同一通道**里既生成音频又生成转写，`【疑似异常】` 里的话会被**念出来**
   （括号本身通常不发音，但「疑似异常」这几个字会），用户会听到一句机器人腔。现在触发句是自然口语：

   ```
   我看到画面这里有问题：   /   我看到画面上有个问题：   /   画面上有个问题：
   ```

   被念出来也自然，而且模型更容易把自然句子放在句首（召回更稳，不必记格式约定）。
   旧标记作为**兼容别名**继续接受（措辞刚换时仍在跑的会话可能还按老格式说，不能静默漏报）。
3. **消费方：只进面板提醒。** 作为“实时模型提醒 · 未核实”与抽帧告警视觉区分，提供
   “交给 AI 排查”和忽略入口。它不进入主 Agent 时间线，也不自动启动 Agent。
4. **网关界限：** 回流文字最多 300 字；相似度不低于 0.82 且 45 秒内去重；两秒节流。
   这些规则限制重复和无界文本，不代表对模型自述的事实核验。

## 0. 为什么做这件事（先看这段再决定值不值得接）

原生实时模式下，画面理解发生在**实时模型**那侧：它看得见画面，但**没有工具**、**不产出结构化
告警**、**说的话也不进主 Agent 上下文**。而 `api.py` 的 `if native_taken: continue` 让抽帧观察
（`live_vision_alerts` 那条告警链）**根本不跑**——所以「AI 主动发现画面问题」原本是断的。

已有两条相关能力，C 是第三条，先看清各自的边际价值：

| | 谁在看 | 产出 | 实时性 | 额外成本 |
|---|---|---|---|---|
| 抽帧观察（原路径） | 视觉模型 | 结构化（observations + **anomalies**） | 1.4s 节流 | 每帧一次模型调用 |
| **A 档旁路观察**（已落地 `9f648b3`） | 视觉模型 | 同上 | `DOCMIND_NATIVE_OBSERVE_INTERVAL` 默认 **5s** | 每 5s 一次模型调用 |
| **C：实时模型自述回流** | 实时模型（本来就在看） | 自然语言，**未核实** | **实时** | **零额外调用** |

→ **C 买的是「实时 + 零额外调用」，代价是可信度更低（可能幻觉）。** 所以 R15-3 的误报/漏报
数字是「该不该默认开启」的决策依据。

## 1. R15-0 · 调研（先做，其余三项都依赖它）

必须定下三件事，产出一页决定记录：

### ① 载体：回流事件长什么样？

- **(a) 复用 `video.observation` + 来源标记**（如 `source: "realtime"`）
  - ✅ 不改协议（`SERVER_TYPES` 一行不动）
  - ⚠️ 语义混用：客户端会把它当「视觉模型观测」处理
  - ⚠️ **有雷**：客户端有一条分支——收到 `ok:false` 或 `audit.mode=unavailable|error` 的
    `video.observation` 就 `socket.close()`（那是给抽帧模式写的）。回流事件必须确保不触发它，
    否则模型一句幻觉就能关掉整条会话（连着语音）。
- **(b) 新增服务端事件类型**（如 `model.observation`）
  - ✅ 语义干净、客户端可完全区别对待
  - ⛔ **必须改 R0 独占的** `agent_runtime/realtime_protocol.py` 与
    `frontend/src/workbench/realtimeProtocol.ts` → 需用户改派或 /root 执行

### ② 触发：怎么从实时模型的自由文本里认出「发现」？

- 建议：让模型**用固定前缀自称**（如「【疑似异常】…」），靠 `DEFAULT_INSTRUCTIONS` 约束——
  命中率高且可控；
- 备选：网关猜关键词（脆，中文口语变体太多）；
- 备选：每轮都落（噪音大，会把对话文本灌进时间线）。

### ③ 消费方：回流给谁？（风险递增）

1. 面板告警横幅（复用 `liveVisionAlert` 的「交给 AI 排查」入口）—— 最安全；
2. R8 时间线（进主 Agent 上下文，标未核实资料）；
3. **自动起一轮 agent** —— 最激进：模型一句幻觉就自动开工，**不建议默认开启**。

## 2. R15-1 · 网关回流管线（依赖 R15-0）

- 落点：`agent_runtime/realtime_bridge.py`（AI-F 的模块，改这里不碰 R0 文件）。
- 做什么：按 R15-0 的标记从 `model.delta` 抽取自述 → 生成回流事件。
- 必须带：**未核实标注**（复用时间线现有措辞）、**按文本相似度 + 时间窗去重**、**限长**、**节流**。
- 验收：同一条异常说十遍**只进一条**；进了必须能被一眼看出去自实时模型、且未核实。

## 3. R15-2 · 前端呈现与安全（可与 R15-1 并行，接口按 R15-0 定）

- 渲染成「实时模型的未核实提醒」，**与抽帧观察在视觉上区分**；复用告警横幅的「交给 AI 排查」。
- **必须绕开**客户端那条 `ok:false / audit=unavailable → socket.close()` 分支。
- 验收：回流在任何情况下都不得影响原生主链路与语音（掉线/静音/丢字都不许发生）。

## 4. R15-3 · 准确性与回归（依赖 R15-1 / R15-2）

- 用假 provider 造「说了异常 / 没说异常」两类样本 + 真机抽查，统计**前缀命中率**与**真实异常
  重合度**，给出误报/漏报数字。
- 补契约测试：事件形状、去重、限长、不打断原生主链路、未核实标注。
- 决策线：**误报率超阈值 → 默认只进面板、不进主 Agent 上下文**（必要时默认关闭）。
