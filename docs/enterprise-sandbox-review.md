# 执行隔离与独立复核

自主开发工作流的普通命令、Python 执行、分区校验、生成的预览适配器，以及最终验收命令，默认使用 `DOCMIND_EXECUTION_MODE=enterprise`。工作流先复制项目到临时试做区。配置 Docker 或 Podman，以及以摘要固定的 `DOCMIND_SANDBOX_IMAGE`（例如 `registry.example.com/docmind/runtime@sha256:<64 位摘要>`）时，命令使用容器；镜像需预装项目所需的 Python、Node、测试器和依赖，容器执行时不拉取镜像。Windows 没有容器时仍使用 Job Object 兼容路径，让 Agent 可以在试做区继续开发，但这条路径不具备容器级文件和网络边界。

容器仅接收一份临时项目副本，不挂载原项目；无网络，关闭特权能力，限制 CPU、内存、进程数量和运行时间。当前没有域名白名单代理，调用者即使请求 `network=true` 也不会开放全网；联网研究仍走已有受审计的搜索工具。项目的 `.env`、常见密钥文件、虚拟环境和 Git 元数据不会复制。命令对容器临时副本的修改不会回写试做区；项目编辑须通过受控文件工具完成。需要通过审批后安装项目工具的旧流程在企业模式下暂时拒绝宿主机安装，待隔离安装和产物导入实现。

Windows 兼容路径用 Job Object 限制进程、内存和时间，但不能隔离宿主文件系统或网络；界面会标记“宿主兼容执行”，独立终审状态仍是 `unverified`，无法通过应用门。不要把它作为企业级容器证据使用。

有项目目录的开发工作流默认先创建 `.docmind/project_stages/<workflow-id>/workspace` 临时试做区。子代理的项目读写上下文会指向这个目录，试做期间只允许项目读写、测试和检索工具；桌面操作、外部文件写入和会改变外部系统的 MCP 调用会被拦截。原项目不会被修改。

工作流结束时，系统根据试做区基线核对实际文件变化，并在容器副本中重新运行项目画像里的 `acceptance_scripts`。报告显示文件差异、命令、退出码和输出。项目发生变化却没有验收命令、快照不完整、隔离后端不可用或测试失败时，结果不会标记为完成。用户可以在任务卡重新测试与复核，也可丢弃该任务的试做区；丢弃不会改动原项目。终审和模型结果均通过后，开发舱会显示“将已验证改动应用到项目”按钮；应用时再次检查原项目没有被外部修改，并按精确差异合并。用户的最终验收仍保留。

`DOCMIND_EXECUTION_MODE=local` 是开发兼容模式，会以当前用户权限运行命令，并在报告中标记 `local_mode`，不能作为隔离或独立复核证据。

当前边界：在自主工作流之外调用文件工具仍可能直接改真实项目；MCP、桌面自动化、网页预览浏览器和部分外部软件启动不在容器内。执行前快照有容量限制且回滚不删除新增文件。必须继续收敛这些宿主入口并完成真实容器联验，才能宣称 Agent 整体达到企业级隔离。开发机未安装 Docker/Podman 时可继续使用兼容试做路径，但不能声称真实容器联验通过。
