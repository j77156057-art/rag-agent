# Agent 双项目拆分记录

目标：稳定开发 Agent 的工具协议、自验证和评测；共享运行时与游戏工具分离；问答入口形成 IT 支持助手的知识回答与确认创建工单流程。现有开发工作台保留。

## 当前阶段（2026-09-19）

用户最终决定采用两个独立文件夹、两个 Git 仓库。本仓库 `rag-agent` 只保留开发问答；IT 查询助手迁移到相邻项目 `docmind-it-assistant`。基于工作区现有代码增量修改；开始时 README.md、agent.py、tools.py、llm.py、pricing.py、run_golden.py、golden/questions_v2.json 已有未提交改动，不能将整文件提交误称为只包含本轮工作。

已落地：

- 新增不依赖游戏模块的 `agent_runtime` 包。`ToolResult` 提供明确的成功状态、错误类型、数据和产物；现有文本工具经适配器保留兼容行为。顺序与并行工具都通过同一异常隔离入口，工具异常消息不直接暴露给模型。
- 自验证返回 `passed / failed / skipped / partial`。校验器故障、无适用检查、缺环境均不能标记通过。校验目标经真实路径检查，拒绝越出项目目录。
- 每次成功写入会使该文件之前的验证失效；按文件聚合最新结果。存在未验证修改时，最终回答和会话历史使用确定性未完成提示，trace 记录 `verification_incomplete`，不把该回合记作成功经验。
- 发布评测门拒绝损坏 JSON、重复 ID、未评分项、缺少基线题目；工具调用判定使用完整工具名，避免 `read_file_unsafe` 被当作 `read_file`。
- `agent_runtime/` 继续提供开发 Agent 的工具结果、自验证与实例级工具注册契约；`applications/developer/` 是开发应用边界。
- 本仓库已移除 IT 页面、`/api/it/*` 路由、IT 数据和打包资源。开发入口 `/`、`/api/chat`、`/workbench` 保持不变。
- 新项目 `docmind-it-assistant` 只提供 `POST /api/query`、查询历史和模型路由状态；`assistant/` 只读知识，`backend/` 负责 SQLite 数据传输与模型调配，不含文件写入、Shell、Git 或游戏工具。
- 新项目独立测试 2/2 通过。真实模型尚未接入；默认使用确定性知识检索，后台仅暴露可配置模型画像。

## 已完成的验收

### 1. 开发 Agent 稳定化

- 第一批工具结果、异常隔离、自验证状态和严格评测门已完成并回归。旧文本工具仍经兼容适配器识别失败，这是明确保留的迁移边界。

### 2. 项目分离

- 开发与 IT 已改为独立文件夹和独立 Git 历史。开发应用继续兼容原 `/api/chat` 与 `/workbench`；IT 项目使用独立端口和 SQLite 文件。

### 3. IT 查询助手

- 按最终要求收窄为只读查询，不再包含草稿或工单创建。数据库与模型调配均在新项目后台目录，不进入查询助手业务层。

## 后续非阻塞项

- 为 IT 回答接入可选 LLM 润色时，必须保留当前确定性检索、引用和确认门，且只使用 IT 注册表。
- 真实企业知识源或工单平台需要单独连接器、认证、审计和数据保留设计；当前明确只是本地演示。
- 真实模型黄金题仍需按固定配置另跑并保留原始结果；本轮单测与浏览器结果不代表模型质量提升。

## 完成证据要求

每项记录代码路径、测试命令和结果；真实模型评测与确定性协议测试分开报告。目标全部实现且验证完成前，保持实施中状态，不以增加页面或生成设计文档替代功能交付。
